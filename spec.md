# Органайзер - Спецификация системы:
**Пет-проект для обучения лучшим практикам frontend & backend & cli разработки.**

## Главные принципы, по приоритетам:
0. **Security приложения**: 
данные пользователя и его пк должны быть под 100% защитой! Ни доли процента не должно быть вреда данных пользователя (потери/повреждения/кражи) или вреда для пк пользователя!

## 1. Концепция: Ядро и два интерфейса
Система строится по принципу: **Единое Ядро + Два интерфейса доступа (CLI и Web UI)**:

```text
               ┌──────────────────────────────────────┐
               │         ЯДРО (organizer/server)      │
               │   Node.js (TS), Fastify, SQLite      │
               │   Хранилище данных, Cron, Плагины    │
               └───────────▲──────────────▲───────────┘
                           │              │
           ┌───────────────┴──┐        ┌──┴───────────────┐
           │  organizer/cli   │        │  organizer/web   │
           │  CLI-интерфейс   │        │  Web-интерфейс   │
           │  + воркер на Mac │        │  (Браузер)       │
           └──────────────────┘        └──────────────────┘
```

1. **Ядро (`server/`)**:
   - Backend-демон на Node.js 22+ (TypeScript).
   - Хранилище данных SQLite (`node:sqlite` с WAL).
   - REST API (Fastify) с токеном авторизации `X-Client-Token`.
   - Планировщик фоновых задач (`croner`).
   - Исполнение серверных хуков плагинов.

2. **CLI-клиент и воркер (`cli/`)**:
   - Консольный интерфейс к ядру (`organizer task add`, `organizer status`).
   - Локальный воркер на macOS: исполнение системных задач, которые сервер не может выполнить напрямую на машине пользователя:
     - Запуск локальных bash-скриптов и утилит (`zx`).
     - Автоматизация браузера через `puppeteer-core` (вход на сайты, сбор данных, автоматические действия).
     - Системные уведомления на macOS.

3. **Web UI клиент (`web/`)**:
   - Графический интерфейс к ядру через REST API для работы в браузере.
   - Стек: Vanilla TypeScript + SCSS + нативный DOM API + Vite (без тяжелых фреймворков).
   - Интерактивный календарь, бэклог по сферам жизни, трекер задач, заметки, таймеры.

## 2. Модель данных задач и приоритеты реализации

### Единая модель задач (`Task` / `/api/v1/tasks`):
Все задачи хранятся в единой таблице `tasks`. Модули интерфейса (`todos`, `backlog`, `kanban`) представляют собой специализированные представления (views) и фильтры по статусам жизненного цикла:

```ts
export type TaskStatus = 
  | 'backlog'      // В бэклоге (идеи, не назначенные на дату)
  | 'todo'         // Запланировано к выполнению
  | 'in_progress'  // В процессе работы
  | 'review'       // На проверке / ревью
  | 'done'         // Выполнено
  | 'archived';    // В архиве
```

### Приоритеты реализации модулей системы:
0. **Список задач (`todos`)**: отображение активных задач (`todo`, `in_progress`, `review`, `done`), связка Web UI с REST API Fastify, оптимистичный UI, нативный DOM API.
1. **Напоминальщик событий (`reminders`)**: события и напоминания с дедлайнами, фоновый планировщик `croner`, Web Notifications API в браузере, системные нотификации macOS через CLI воркер.
2. **Бэклог задач (`backlog`)**: буфер входящих задач со статусом `backlog`, быстрый перевод в работу (смена статуса на `todo`) или в напоминание.
3. **Задачник в виде столбцов (`kanban`)**: Trello-подобная доска из 5 столбцов (`Backlog` ➔ `Todo` ➔ `In Progress` ➔ `Review` ➔ `Done`) на нативном **HTML5 Drag & Drop API** (без внешних библиотек) + CSS Grid/Flexbox. Перетаскивание меняет `status` через `PATCH /api/v1/tasks/:id`.
4. **Графический календарь (`calendar`)**: сетка месяца/недели на **CSS Grid**, отображение событий из `reminders` и задач с `dueDate` из `todos`, адаптив под 4-5 брейкпоинтов, микро-анимации на `transform`/`opacity`.

## 3. Плагины (Split-архитектура)
Плагины должны быть максимально легковесными и разделяться по зонам ответственности:
- `manifest.yml` — описание, конфигурация, триггеры.
- `server/` — серверная логика (БД, cron-расписание, хуки `onReady`, `onSync`, `onSchedule`).
- `cli/` — клиентская логика на ПК (`onInit`, `onCommand`, `onBrowserTask`, bash-скрипты, puppeteer).
- `web/` — UI-компонент для отображения в браузере.

### Дополнительные плагины:
5. **Таймер (`timer`)**: интервалы, выполнение скриптов/команд по расписанию.
6. **Обновление окружения (`updater`)**: автоматический опрос обновлений brew/npm на локальном Mac.
7. **Веб-автоматизация (`browser-automation`)**: авторизация на сайтах, переход в разделы, клики/сбор данных (puppeteer/curl).
8. **Лунная позиция (`moon-phase`)**: расчет лунных фаз и событий (suncalc).

## 4. Стек и принципы разработки
- Разработка ведется **локально на macOS**.
- Пакетный менеджер: **`npm`**.
- Тестирование: **`vitest`** (TDD подход к критическим модулям ядра и плагинов).
- Никакого оверинжиниринга: чистый код, минимальный объем внешних зависимостей.
