# Отчёт: Шаг 8a.3 — планирование срабатываний и догон (2026-09-17)

Шаг закрыт в `plan.md` галкой со строкой «сделано, коммит `4e46df9`» — без моих дописок. Проверено: тесты 57/57 (server) + 5/5 (cli) + 23/23 (web), `npm run build` зелёный.

## Что сделано и почему

1. **Планирование срабатывания ушло в хранилище, а не в роут** (`server/src/db/index.ts:373`, `planEventReminder`): DELETE невыданных строк события + `INSERT … ON CONFLICT(event_id, fire_at) DO NOTHING`. Хук вызван из `createEvent` (`:278`) и `upsertEvent` (`:603`), потому что в `events` пишут два входа — `POST /api/v1/events` и `POST /api/v1/sync`. Хук в роуте оставил бы второй вход без напоминаний.
2. **Атомарная выдача** (`claimDueReminders`, `db/index.ts:403`): выборка просрочки и пометка «выдано» — одна транзакция (`transaction()`, `:448`; вложенных транзакций SQLite не умеет) плюс инвариант «прочитано = помечено»: расхождение — ROLLBACK и исключение, а не тихий дубль. Догон — условие `fire_at <= now`, иначе закрытый на ночь ноутбук молча теряет напоминания.
3. **Минутный тик — штатной джобой планировщика** (`server/src/reminders.ts`, `registerReminderDispatch` → `* * * * *`, дедуп по `action`: `addJob` даёт новый `id` каждый вызов, и без поиска по действию каждый рестарт плодил бы строку расписания). `runReminderTick(db, now)` тем же проходом чистит выданное старше retention — иначе у чистки не осталось бы ни одного прод-вызова.
4. **Тесты — 11 шт.** (`server/test/reminders-dispatch.test.ts`), у каждого в комментарии записано, какое изменение кода его краснит: план из POST, интервал `0`, «ровно один раз», догон на трёх часах, снятие интервала и перенос начала через sync, повторная синхронизация после выдачи, чистка retention, выживание пометки после рестарта (файловая БД), одна строка джобы и её работа через `triggerJob`. Хелпер `delivery-log.test.ts` остался без `reminderMinutes`, чтобы счётчики журнала не считали строки, запланированные хуком шага.
5. **Интервал `0` чинился в трёх местах сразу** (`|| null` при записи события, `!value` в планировании, `|| undefined` в `mapEventRow`) — все три стали `??`: значение «напомнить в момент начала» терялось молча.
6. **Сборка починена попутно, к шагу не относится:** `npm run build` был красным с Шага 7b.1.2 (две ошибки типов в `web/`, `vitest` их не видит — он стирает типы). Поведение не менялось.
