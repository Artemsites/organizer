# DECISIONS.md (ADR)
Журнал архитектурных решений.

## 2026-09-14: Выбор npm workspaces для монорепозитория
- **Проблема**: В плане упоминался `pnpm workspaces`, однако в основном проекте и окружении используется стандартный `npm`.
- **Решение**: Настроили `npm workspaces` в корневом `package.json` (`server`, `cli`, `web`, `shared`).
- **Причина**: Нативность из коробки, отсутствие необходимости ставить сторонний пакетный менеджер, 100% совместимость с Node.js.

## 2026-09-14: Использование встроенного модуля `node:sqlite` (WAL)
- **Проблема**: Необходимость легковесной встроенной БД без необходимости поднимать отдельный сервер PostgreSQL/MySQL.
- **Решение**: Использовать встроенный в Node.js 22.5+ синхронный модуль `DatabaseSync` из `node:sqlite` с режимом WAL (`PRAGMA journal_mode = WAL;`).
- **Причина**: Нулевой оверхед, нет компиляции нативных бинарников (в отличие от `better-sqlite3`), максимальная скорость чтения/записи.

## 2026-09-14: Архитектурное разделение CLI-воркера и Web UI
- **Проблема**: Необходимость как удобного графического интерфейса для человека, так и возможности автоматизации системных задач (скрипты, brew, puppeteer).
- **Решение**: Выделены два независимых клиента: `organizer/cli` (консоль + локальный агент-воркер на Mac) и `organizer/web` (визуальный SPA на чистом DOM/TS/SCSS без фреймворков). Оба общаются с ядром через единый REST API.
- **Причина**: Удаленный сервер не может исполнять bash-команды на локальной машине пользователя. Воркер на Mac закрывает эту задачу.

## 2026-09-14: Приоритет локальной разработки на Mac перед Beget
- **Проблема**: Шаг 1 плана требовал проверки хостинга Beget и Passenger.
- **Решение**: Деплой на Beget перенесен в Шаг 9 (финальный), вся первичная разработка и TDD-тестирование ведутся локально на macOS.
- **Причина**: Ускорение цикла обратной связи и отладки архитектуры без сетевых задержек и зависимостей от удаленного хостинга.

## 2026-09-14: Транспорт Web → Ядро — прокси Vite, а не CORS
- **Проблема**: Web (`:5173`) и ядро (`:3000`) на разных origin. Нужен доступ к REST API, при этом `X-Client-Token` — общий секрет, и в бандле браузера он виден любому, кто открыл страницу (принцип 0 spec.md).
- **Решение**: `server.proxy` в `web/vite.config.ts`, логика вынесена в `web/vite.proxy.ts` (`createApiProxy`). Токен подставляет сам прокси на событии `proxyReq`, читая его через `loadEnv(mode, <корень репо>, '')`. Пакет `@fastify/cors` не ставится.
- **Причина**: Same-origin снимает CORS и preflight целиком (быстрее), а секрет остаётся в Node-процессе Vite и в клиентский код не попадает. Проверено: сборка прогрепана на тестовый токен — пусто.
- **Запрет**: токен никогда не читать через `import.meta.env` / `VITE_*` — такие переменные Vite встраивает в бандл.

## 2026-09-14: Конфигурация — один `.env` в корне, без пакета `dotenv`
- **Проблема**: Секреты нужны и серверу, и конфигу Vite; два источника разъедутся.
- **Решение**: Один `.env` в корне монорепо (в `.gitignore`), образец — `.env.example`. Сервер читает его нативным флагом Node `--env-file-if-exists`, Vite — через `loadEnv` с пустым префиксом.
- **Причина**: Нативный механизм вместо зависимости (принцип 2.1 spec.md). Проверено на Node 24.

## 2026-09-14: Драйвер браузерной автоматизации — `playwright` вместо `puppeteer-core`
- **Проблема**: Плагину `browser-automation` нужно надёжно работать вместо человека на JS-сайтах.
- **Решение**: `playwright`. `spec.md` §1/§3/§3.7 обновлён по разовому разрешению хозяина.
- **Причина**: Скорость у обоих одинаковая — её задаёт Chromium, а не библиотека. Решают авто-ожидания (у puppeteer каждый клик обрастает ручными `waitFor`, и именно они флакуют на медленном сайте), дешёвые изолированные контексты и `storageState` для переиспользуемого логина.
- **Следствие**: пункт AUDIT.md про Chromium для puppeteer устарел, см. запись от 2026-09-14 в AUDIT.md.

## 2026-09-14: Сборщик фронтенда — Vite, Gulp вычеркнут
- **Проблема**: `TODO.md` требовал навык Gulp («у нас Gulp»), `spec.md` и написанный код — Vite. Оба файла P0.
- **Решение**: Vite. Gulp из списка навыков убран хозяином.
- **Причина**: Второй сборщик в проекте, объявленном минималистичным, противоречит принципу 2. Навык Gulp при надобности отрабатывается в отдельном репозитории.

## 2026-09-14: GSAP — только там, где нативного не хватает
- **Проблема**: `TODO.md` требует навык GSAP (таймлайны, ScrollTrigger), `spec.md` §2.1 требует нативное там, где оно эффективно.
- **Решение**: По умолчанию CSS-переходы, `@keyframes` и Web Animations API. GSAP подключается по факту упора — сложные секвенции и ScrollTrigger, в первую очередь на лендинге (статика, бюджет ядра не тратится).
- **Причина**: ~70 КБ в ядро ради навыка противоречат принципу 1 (быстрота); на лендинге этой цены нет.
