# Органайзер: Memory

## Архитектура: Ядро и Интерфейсы

Система состоит из единого Ядра (Server) и двух типов интерфейсов-клиентов (CLI и Web UI):

```text
                  ┌──────────────────────────────────────────────┐
                  │          ЯДРО (organizer/server)             │
                  │   Backend-оркестратор + Fastify REST API     │
                  │   SQLite (node:sqlite WAL) + croner          │
                  │   Серверная бизнес-логика плагинов           │
                  └──────────────▲────────────────▲──────────────┘
                                 │                │
                     REST API    │                │  REST API
                  (X-Client-Token)│               │
                                 ▼                ▼
         ┌───────────────────────────────┐   ┌───────────────────────────┐
         │       organizer/cli           │   │      organizer/web        │
         │   Консольный интерфейс +      │   │    Графический интерфейс  │
         │   Локальный воркер (Mac/Linux)│   │       (Браузер)           │
         │   - CLI-команды в терминале   │   │   - Визуальный UI         │
         │   - Запуск bash / zx / node   │   │   - Календарь, доски      │
         │   - Puppeteer (веб-робот)     │   │   - Быстрый ввод задач    │
         └───────────────────────────────┘   └───────────────────────────┘
```

### 1. Ядро (`organizer/server/`)
- Главный оркестратор системы и хранилище данных.
- Технологии: Node.js 22.5+ (TS), Fastify, `node:sqlite` (режим WAL), croner, zod.
- **Хранение данных (SQLite):**
  - Таблицы: `events`, `tasks`, `reminders`, `plugins_state`, `jobs`, `clients`.
  - Дневник — локальные markdown-файлы.
- **Планировщик фоновых заданий:** `croner` (задачи, таймеры, триггеры клиентов).
- **REST API:** эндпоинты `/api/v1/*` с заголовком авторизации `X-Client-Token`.
- Раздача клиентских сборок плагинов и синхронизация состояния.

### 2. Консольный интерфейс и воркер (`organizer/cli/`)
- Интерфейс управления из терминала + локальный исполнитель на macOS.
- Технологии: Node.js (TS), `cac` (парсинг CLI), `zx` (bash/zsh скрипты), `puppeteer-core`, native fetch.
- Функции:
  - Управление через терминал: `organizer task add "..."`, `organizer status`.
  - Авторизация и pull клиентских частей плагинов с динамическим `import client/entry.ts`.
  - Выполнение задач с доступом к локальной ОС (bash-скрипты, brew/npm update).
  - Управление виртуальным headless-браузером (`puppeteer-core`) для автоматизации сайтов.

### 3. Графический веб-интерфейс (`organizer/web/`)
- Визуальный интерфейс для комфортной интерактивной работы в браузере.
- Технологии: Vanilla TypeScript, Dart Sass (SCSS `@use`), чистый DOM API, Vite.
- Функции:
  - Наглядное представление: календарь, бэклог по сферам жизни, канбан/списки дел, заметки.
  - Мгновенная отзывчивость без тяжелых фреймворков.

### 4. Плагины (`organizer/plugins/`)
- Split-архитектура плагинов:
  - `manifest.yml` — описание, конфигурация, триггеры.
  - `server/entry.ts` — серверные хуки (`onReady`, `onSync`, `onSchedule`), работа с SQLite.
  - `client/entry.ts` — клиентские хуки воркера (`onInit`, `onCommand`, `onBrowserTask`), bash-скрипты, puppeteer.
  - `web/entry.ts` — визуальные компоненты / страницы в браузере.

## Структура директорий монорепозитория
```text
organizer/
├── server/       # Ядро (Backend-оркестратор: Fastify, SQLite, croner)
├── cli/          # Терминальный интерфейс и системный воркер (cac, zx, puppeteer)
├── web/          # Графический веб-интерфейс (Vite, TS, SCSS, DOM) [каркас готов]
├── plugins/      # Плагины (split: server + cli + web)
├── shared/       # Общие типы, контракты API и DTO
├── spec.md       # Спецификация проекта
├── plan.md       # Пошаговый план разработки
└── memory.md     # Архитектурная память
```

## Стек и окружение
- **Среда разработки:** локально на macOS (Node.js 24+).
- **Пакетный менеджер:** `npm workspaces` (нативно, быстро, надежно).
- **Тесты:** `vitest` (unit и integration тесты).
- **Деплой (будущий этап):** Beget (Passenger, cron fallback).

## Решения (2026-09-14)

- **Транспорт web → ядро:** не CORS, а прокси Vite (`/api` → `http://127.0.0.1:3000`). `X-Client-Token` подставляет прокси в Node-процессе Vite, в браузерный бандл секрет не попадает (принцип 0). Логика — `web/vite.proxy.ts`, читается через `loadEnv(mode, <корень репо>, '')`. **Запрещено** читать токен через `import.meta.env`/`VITE_*`: такие переменные Vite встраивает в клиентский код.
- **Конфигурация:** один `.env` в корне монорепо, образец — `.env.example`. Сервер читает его нативным `--env-file-if-exists` (Node 22+), без пакета `dotenv`.
- **Драйвер браузерной автоматизации:** `playwright` вместо `puppeteer-core` — авто-ожидания, дешёвые контексты, `storageState`. Скорость определяет Chromium, а не библиотека. `spec.md` обновлён 2026-09-14 по разовому разрешению хозяина.
- **Статический генератор лендинга:** Hugo или Astro — выбор отложен до Шага 21.
- **Окружение хозяина:** глобальный `HTTP_PROXY=127.0.0.1:1080`. Любой `curl` к локальным портам делать с `NO_PROXY='*'`, иначе 502 от прокси, а не ответ сервиса.
