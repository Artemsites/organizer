# Issues: техдолг и находки вне Scope

Уязвимости и расхождения, найденные при ревью. Заведены шагами в `plan.md`, здесь — чтобы не потерялись.

- **Произвольное выполнение кода на машине хозяина.** `cli/src/plugin-loader.ts:41` (`loadFromCode`) скачивает JS с сервера и делает `import()` в основном процессе Node, плюс выдаёт плагину `exec` через `zx`. Подписи нет, песочницы нет, whitelist нет. Блокер всех плагинов — Шаг 16.5. Референсы: extension host у VS Code, разрешения в манифесте у Joplin.
- **Сервис открыт в локальную сеть с известным секретом.** `server/src/index.ts` слушает `0.0.0.0`, `server/src/auth.ts` держит `DEFAULT_TOKEN` фолбэком. Шаг 7.0.1.
- **Записи без валидации.** `POST`/`PATCH /api/v1/tasks` пишут в SQLite любую строку; `zod` в зависимостях есть, но не используется. Шаг 7.0.2.
- **Инъекция AppleScript.** Текст напоминания приходит с сервера и уйдёт в `osascript` — передавать аргументом или через stdin, не склейкой строки. Тот же запрет на `zx`-вызовы плагинов. Шаг 8c.
- **Шаг 6 был отмечен сделанным, но `puppeteer` не установлен** — браузерная автоматизация не сделана, перенесена в Шаг 19 (уже на `playwright`).
- **Раздвоение модели задач.** `shared/src/models.ts` держит `BacklogItem` со своими статусами и полем `sphere`, конкурируя с единой таблицей `tasks` из spec.md §2. Удаление — Шаг 9.
- **`TaskStatus` рассинхронизирован со spec.md** — 4 значения вместо 6. Шаг 7a.
- **Полная перерисовка `innerHTML`** в `web/src/modules/todos/todos-module.ts` делает оптимистичный UI и анимацию смены статуса недостижимыми. Шаг 7b.
- **`web/` почти без тестов.** Есть только `web/test/proxy.test.ts` (4 кейса), модули UI не покрыты.

## Открытые вопросы

- **Генератор статики для лендинга — Hugo или Astro?** Шаг 21. Astro сам на Vite: TS, SCSS и конфиг — тот же стек, что в `web/`, плюс ноль JS по умолчанию. Hugo быстрее собирает и даёт другой стек (Go-шаблоны) — больше нового навыка, но и больше времени. Решать перед стартом шага.
