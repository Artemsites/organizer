# План: Органайзер (Ядро и два интерфейса CLI & Web)

## Архитектура монорепозитория
```text
organizer/
├── server/       # Ядро: Fastify REST API, node:sqlite (WAL), croner
├── cli/          # Интерфейс терминала + локальный воркер на macOS (cac, zx, puppeteer)
├── web/          # Графический интерфейс в браузере (Vite, Vanilla TS, SCSS)
├── plugins/      # Плагины (split: server + cli + web)
├── shared/       # Общие типы, DTO и контракты плагинов
├── spec.md       # Спецификация
├── plan.md       # План разработки
└── memory.md     # Архитектурная память
```

> Требования и приоритеты — в [spec.md](./spec.md). Здесь только план работ.
> Навыки, ради которых пишется код, — в [TODO.md](./TODO.md).

## 1. Концепция: Ядро и два интерфейса

* Система строится по принципу: **Единое Ядро + Два интерфейса доступа (CLI и Web UI)**.
* Доступ ко всему API должен быть в полной мере как в cli так и в web, то есть по сути должно работать через адаптер и покрывать друг друга как полный аналог.

## Порядок выполнения

Номера шагов исторические, читать план сверху вниз **нельзя** — порядок такой:

```text
7.0 → 7.0.1 → 7.0.2 → 7.0.3 → 7a → 7b   блокеры + Приоритет 0
  → 13                          SCSS-архитектура и брейкпоинты (фундамент всей вёрстки ниже)
  → 8a → 8b → 8c → 9            reminders, backlog
  → 14                          UI-кит (когда есть 3 реальных потребителя, не раньше)
  → 10 → 11                     kanban, calendar
  → 15 → 16                     производительность, линтеры и деплой-скрипт
  → 16.5 → 17 → 18 → 19 → 20    песочница, затем плагины
  → 21 → 12                     лендинг, выпуск
```

**Режим наставника.** `spec.md` требует объяснять применённый best practice **в комментариях к коду, а не в сессии терминала**, и попутно учить английским понятиям программиста. Значит в каждом шаге объяснение — часть кода, а не часть ответа в чат. Пример нужного уровня — `server/src/auth.ts` из Шага 7.0.1.

**Режим работы — парное микрошаговое программирование** (`TODO.md`): цель проекта — навык хозяина, не скорость выпуска. Шаг берётся через `/i-step-pair`, по одному, тесты запускает хозяин. Теги `[Model:]` показывают сложность шага и страхуют передачу, а не назначают автономного исполнителя. Детализация шага — каркас и страховка от ошибки, а не наряд на работу без хозяина.

Жёсткие зависимости: 13 до 10 и 11 (иначе адаптив пишется дважды), 14 после 7b, 16.5 до любого плагина, 16 до 12.

### Сквозное правило: агент и скрипт — тоже источник угрозы

Принцип 0 `spec.md` теперь прямо называет автоматических агентов. Это касается и нас самих, а не только чужих скриптов:

- **Секреты не попадают в память задачи.** `.env` с рабочим токеном лежит в корне, и любой агент, читающий репозиторий, его видит. Значение токена не цитировать ни в `plan.md`, ни в `memory.md`, ни в `report.md`, ни в `submit.md` — только имя переменной.
- **Плагин и хук исполняют чужой код.** Всё, что приходит с сервера или из плагина, считается недоверенным: никакой склейки строк в `zx`, `osascript` и SQL, никакого `import()` неподписанного кода (Шаги 8c, 16.5).
- **Необратимое — только по команде хозяина.** `git push`, удаление файлов, установка пакетов на машину. Гейт фаз в Якоре — не формальность, а часть принципа 0.

| 7a, 9, 10 (модель задач) | **Vikunja** (Go + Vue, AGPL) | Ровно наша схема из spec.md §2: одна сущность задачи и несколько представлений над ней (список / канбан / таблица / гант). Смотреть, как устроены фильтры и сохранённые представления, и где у них проходит граница «статус задачи» vs «колонка доски» — у нас это Шаги 7b и 10, и разъехаться они могут легко. |

Перед чтением любого из них — **проверить актуальность и лицензию** (список составлен по состоянию на 2026-09-14, проекты меняют статус). Вывод по каждому разбору — 3–5 строк в `memory.md`, а не пересказ документации.

### Открытые вопросы

1. **Генератор лендинга:** Hugo или Astro (Шаг 21). Решается перед стартом шага.
2. **Драйвер браузера:** `puppeteer-core` (как в spec.md §1) или `playwright` (Шаг 19). Playwright удобнее в работе — авто-ожидания вместо ручных `waitFor`, дешёвые изолированные контексты, лучше отладка; скорость у обоих одинаковая, её задаёт Chromium, а не библиотека. Смена значения в spec.md требует явного разрешения хозяина.

Это произвольное выполнение кода на Mac хозяина по команде сервера: подписи нет, песочницы нет, whitelist нет. Блокер Шага 17, вынесен отдельным шагом ниже.
